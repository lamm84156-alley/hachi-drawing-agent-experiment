# Design authority and pending freeze

Primary authority: final English proposal.pdf, Library `libfile_c17dc54b9ed881919f0e3e42064b7ac9`, version 19 (five pages); editable `proposal_en_5pages.md`, Library `libfile_d4dd3cd9223881918b5b3da3d6a61723`, version 1. Both were read fully via Library on 2026-11-04. The supported prepare_materialize/helper download failed for both files; source bytes are not archived locally. No claim of byte-identical local verification is made.

Research question: whether original human demonstration order improves cartoon-face completion over randomly reordered demonstrations; No Demo is a reference. One demonstrator, fixed VLM weights/version and decoding. Each demonstration matches target parts but varies proportions. Reordered demonstrations replay identical additive paths from a blank canvas; all intermediate canvases are recomputed. Full context, no semantic step labels, retrieval or optimization. Human recordings and target designs are not yet supplied.

Controls: black fixed-width pen, one connected path of up to four cubic Bézier segments per draw; undo last path; stop. All commands, including invalid commands and empty undo, use the 40-command budget. Transport failure is a separately logged infrastructure failure, not a model action. Coordinates use normalized [0,1]; off-canvas controls are rejected as an implementation convention to freeze in pilot. DiffVG CPU rendering, 2×2 samples and seed 0 are fixed implementation choices, not research conditions.

Original design: six development and twenty evaluation templates, disjoint; 20 × 5 × 3 = 300 evaluation runs. User requested a 54-run exploratory first stage, not authorized to run yet. Allocation of targets × repetitions is UNDECIDED (must multiply to 18); do not silently select 6×3 or 9×2. The 40-command cap is unchanged. Randomize run order and record schedule, permutation and supported execution seeds. Each reordered run gets a seeded non-original permutation; different seeds may coincidentally yield the same permutation.

Freeze before paid pilot: exact model version returned by provider, endpoint and supported decoding/seed fields, resolution, pen width, history length, output/context limits, target prompt, demonstration context fit, human materials, budget approval. The adapter currently implements Chat Completions JSON text output; provider compatibility is unverified. It does not truncate demonstration context or silently switch guidance. `context_limit_tokens` is recorded, but provider-specific image/context estimation remains a preflight requirement; the API may reject an oversized packet.

Freeze rubric on development targets: specified parts, valid-shape definitions, center and size tolerances, scalar layout error definition and redraw threshold. The proposal leaves numerical tolerances and layout-error aggregation unspecified. They remain user/reviewer decisions, not defaults. Primary completion requires two independent condition-blind ratings, agreement and Cohen's kappa before discussion, and a distinct third adjudicator for remaining disagreements. No automatic completion judgment is implemented.

Primary estimate: equally weight target-level Original minus Reordered completion rates; report percentage points and 95% percentile interval from exactly 10,000 paired whole-target bootstrap draws, keeping all conditions/repetitions together. Exploratory denominator is the actual chosen target count and must be disclosed. Secondary metrics: normalized part-center and bounding-box-size errors, omissions, total commands, invalid actions and redraws. Redraw fails if same-part layout error fails to decrease OR remains above the development threshold. Command counts must be interpreted with completion, and alternative valid drawing orders are accepted.

Audit revision: a single shared development/evaluation material registry is required before a campaign, with original asset hashes and template IDs. The same registry must be referenced by the approved real pilot and formal campaign. Per-run runtime fingerprints record Python/package versions and hashes of application code, DiffVG bindings and the compiled renderer. Resume across code/renderer changes fails rather than silently reusing cached outputs. Raw invalid action content remains in the researcher response logs; model history and rater exports use null action plus validity status. These conventions must be fixed before the real pilot.
